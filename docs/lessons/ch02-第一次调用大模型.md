# 第 2 章 第一次调用 DeepSeek：理解大模型 API 的"语言"

> 本章目标：绕过一切框架，用最原始的 HTTP 请求直接调用 DeepSeek，看清大模型 API 的"语言"长什么样。
> 为测试铺垫：这个请求体/响应体就是第 6 章接口测试的断言对象。

## 1. 四个核心概念（每个配例子）

### 1.1 API Key —— 你的"员工工牌"
去银行办事要身份证，调大模型 API 要 API Key。它做两件事：
1. **证明你是你**（身份认证）
2. **决定你能调多少次、花多少钱**（配额与计费）

格式通常是 `sk-` 开头的一长串随机字符。**绝对不能提交到代码仓库**——谁拿到谁就能用你的额度。
我们把它放在环境变量或 `.env` 文件里，`.gitignore` 排除。

### 1.2 鉴权（Authentication）—— 把工牌亮给窗口看
HTTP 请求头里加一行：
```
Authorization: Bearer sk-xxxxxxxxxxxxxxxx
```
`Bearer` 是协议类型，后面跟你的 Key。服务器收到这个头，才知道"哦，这是合法用户，放行"。

### 1.3 请求体（Request Body）—— 你在窗口填的"表格"
调用大模型的"表格"长这样（JSON 格式）：

```json
{
  "model": "deepseek-chat",
  "messages": [
    {"role": "system", "content": "你是一个友好的AI助手。"},
    {"role": "user", "content": "你好，请介绍一下自己。"}
  ],
  "temperature": 0.7,
  "max_tokens": 500
}
```

逐字段解释：
- `model`：用哪个模型。DeepSeek 的对话模型叫 `deepseek-chat`（相当于 GPT-3.5 级别的通用模型）。
- `messages`：**核心字段**，一个数组，按顺序列出"对话历史"。每条消息有 `role`（角色）和 `content`（内容）。
  - `system`：人设指令，用户看不见但模型必须听。比如"你是电商客服，只回答售后问题"。
  - `user`：用户说的话。
  - `assistant`：模型之前答过的话（用于让它"记住"上下文，第 4 章会用到）。
- `temperature`：0~2，默认 1.0。控制"创造性"：
  - 0 = 几乎确定性输出（适合测试、事实问答）
  - 1 = 默认平衡
  - 2 = 最随机（适合创意写作）
  - **对测试的影响**：同一个 prompt，temperature=0 时两次回答几乎一样；temperature=1 时可能不同。这是 AI 测试独有的变量。
- `max_tokens`：最多返回多少 token。超了会被截断。

### 1.4 响应体（Response Body）—— 窗口递给你的"回执"
服务器返回的 JSON 长这样（简化版）：

```json
{
  "choices": [
    {
      "message": {
        "role": "assistant",
        "content": "你好！我是 DeepSeek Chat，一个由深度求索公司开发的智能助手..."
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 20,
    "completion_tokens": 50,
    "total_tokens": 70
  }
}
```

- `choices[0].message.content`：模型的回答正文。
- `finish_reason`：为什么停下来了。`stop` 是正常结束，`length` 是 max_tokens 到了被截断。
- `usage`：这次调用花了多少 token。计费按 `total_tokens` 算。

## 2. 注册 DeepSeek 拿 API Key

1. 打开 https://platform.deepseek.com/
2. 注册账号（手机号/邮箱）
3. 进入控制台 → API Keys → 创建新 Key
4. 复制 Key（`sk-` 开头），**不要泄露**

新用户一般送免费额度（如 500 万 token），够学完整个课程。

## 3. 代码：20 行直连大模型

```python
import os
import requests

API_KEY = os.environ.get("DEEPSEEK_API_KEY", "")
URL = "https://api.deepseek.com/chat/completions"

headers = {
    "Authorization": f"Bearer {API_KEY}",
    "Content-Type": "application/json",
}

data = {
    "model": "deepseek-chat",
    "messages": [
        {"role": "system", "content": "你是一个友好的AI助手。"},
        {"role": "user", "content": "你好，请介绍一下自己。"},
    ],
    "temperature": 0.7,
    "max_tokens": 500,
}

resp = requests.post(URL, headers=headers, json=data)
print("状态码:", resp.status_code)
print("回答:", resp.json()["choices"][0]["message"]["content"])
print("Token 用量:", resp.json()["usage"])
```

逐行解释：
- `os.environ.get("DEEPSEEK_API_KEY", "")`：从环境变量读 Key，没设置就是空字符串。
- `requests.post(URL, headers=headers, json=data)`：发 POST 请求，`json=data` 自动把 dict 转成 JSON 字符串并设置 `Content-Type: application/json`。
- `resp.json()`：把响应 JSON 解析成 Python dict。

## 追问记录

### Q1：max_tokens 是单次对话的限制，还是包含整个对话历史？

**答：只限制本次回答的输出长度，不包含历史；历史占用的是另一层额度——上下文窗口。**

两层容量：
- `max_tokens`：约束本次输出（completion_tokens）的上限。
- 上下文窗口（DeepSeek 为 64K）：约束 `system + 全部历史 + 本次回答` 的总量。

关系式：`prompt_tokens(输入=人设+全部messages)`，`completion_tokens ≤ max_tokens`，
且 `prompt + completion ≤ 64K`。历史堆到接近窗口上限时，请求直接报 400。

测试推论：
1. 断言 `finish_reason`：`length`=被 max_tokens 截断，`stop`=正常说完（不要数字符）。
2. "超长 messages 数组 → 400" 是第 6 章必测的边界场景（第 4 章多轮对话后会真实触发）。
