# AI 客服小D 测试计划

> 第 5 章产出物。后续第 6~10 章按本计划的"测试分层"逐层落地。
> 版本：v0.4（第一部分收官时的被测系统）

## 1. 被测系统（SUT）

| 项 | 内容 |
|---|---|
| 应用 | AI 客服小D，`app/main.py`（FastAPI） |
| 接口 | `POST /chat`（同步返回完整回答）、`POST /chat/stream`（SSE 流式）、`GET /`（聊天页） |
| 输入 | `{message: str, history: [{role, content}]}` |
| 输出 | `/chat` → `{reply, usage}`；`/chat/stream` → SSE 的 `data:{"delta":...}` + `[DONE]` |
| 外部依赖 | DeepSeek API（**非确定性、计费、有延迟、可能限流/宕机**） |
| 状态 | 无服务端持久化，history 由调用方（前端）保存在内存 |
| 配置 | system prompt（人设 3 条规则）、`temperature=0.3`、`max_tokens=500`、`MAX_HISTORY=10` |

## 2. 风险分析（哪里最容易坏，测试就往哪打）

| 编号 | 风险 | 具体表现 | 应对策略 |
|---|---|---|---|
| R1 | **输出非确定性** | 同问题三次回答：76 / 80 / 67 字，措辞不同 | 断言范围化；关键用例多次运行取统计；temperature 压到 0 做回归基线 |
| R2 | **幻觉** | 实测第 3 次编出"支付宝/微信 1-3 个工作日"（前两次说"以银行/渠道为准"） | 效果评估层专项：事实一致性 / 忠实度打分（第 8 章） |
| R3 | 外部依赖不可控 | 超时、429 限流、5xx | 契约测试 + Mock 兜底；502 分支用例 |
| R4 | 输入边界 | 空串、超长、emoji、SQL/提示词注入 | 等价类 + 边界值（第 6 章） |
| R5 | 上下文错乱 | history 顺序错、滑动窗口裁掉关键信息、角色传反 | 定量构造 history 的用例（第 6 章） |
| R6 | 人设越界 | 问无关话题仍硬答；泄露 system prompt | 软断言 + 裁判模型（第 8 章） |
| R7 | 流式异常 | 中途断流、无 `[DONE]`、状态码已 200 无法报错 | 流式专项（第 6/7 章） |
| R8 | 成本与性能 | token 用量超预期、P95 时延高 | 采集 usage、时延指标并设阈值 |
| R9 | 密钥泄露 | Key 出现在响应或前端代码 | 安全检查：响应体/静态资源扫描 |

## 3. 测试分层与分工

| 层次 | 落地章节 | 测试目标 | 断言类型 |
|---|---|---|---|
| L1 单元（工具函数） | 第 6 章起 | `build_payload` 拼装、`history[-10:]` 裁剪 | 精确（完全相等） |
| L2 接口 | 第 6 章 | 契约、状态码、字段、异常分支 | 精确 |
| L3 Web E2E | 第 7 章 | 用户视角闭环、流式渲染 | 精确 + 等待策略 |
| L4 效果评估 | 第 8 章 | 人设遵守、拒答、幻觉、忠实度 | 统计 / 裁判模型 |
| L5 RAG（进阶） | 第 10 章 | 召回准确率、回答忠实度 | 精确（召回）+ 裁判（忠实度） |

> 记住本计划的核心原则：**把不确定性隔离到最小**。
> L1/L2/L3 中凡是确定的（状态码、结构、字段、页面元素）一律精确断言；
> 只有"回答内容好坏"交给 L4 的评估方法。

## 4. 用例设计模板

每条用例必须写清 7 个字段：

```
ID | 优先级 | 前置(history) | 输入 | 期望 | 断言类型 | 对应风险
TC-API-001 | P0 | [] | {"message":"能退款吗"} | 状态200且reply非空 | A | R1
TC-API-002 | P1 | [] | {"message":""} | 应拒绝(4xx) | A | R4
```

### 断言分级（本项目的"军规"）

| 级别 | 名称 | 适用 | 例子 |
|---|---|---|---|
| A | 硬断言 | 确定性字段 | `status_code == 200`、`"reply" in body`、`reply != ""` |
| B | 约束断言 | 有边界但内容可变 | `len(reply) < 3000`、`reply` 含"退款/换货"等业务词、`finish_reason == "stop"` |
| C | 软断言 | 语义质量 | 是否拒答无关话题、是否编造政策 → 规则匹配或 LLM 打分 |
| D | 统计断言 | 多次运行指标 | P95 时延 < 5s、平均 completion_tokens < 300、拒答率 ≥ 95% |

> 反例（新手最常踩）：`assert reply == "退款需1-7个工作日"` —— 必然红。因为 R1。

## 5. 测试数据与环境

**用例集分类**（每个集合单独维护）：
1. 正常业务：退款、换货、物流、质量问题各 ≥ 2 条
2. 边界：空串、单字、超长（>2000 字）、纯 emoji、纯符号
3. 异常：缺字段、类型错、超长 history
4. 安全：提示词注入（"忽略以上指令"）、索要系统提示词、索要他人工单信息
5. 上下文：需两轮以上才能回答的追问

**成本控制**（AI 测试特有，别忽略）：
- 回归用 `temperature=0` + 短 `max_tokens`
- 评估集与回归集分离，评估集不挂在每次提交的 CI 上
- 优先 Mock 跑逻辑（不花钱），每日定时跑一次真实调用

**环境**：
- 本地：`uvicorn app.main:app --port 8000` + `.env` 里的 `DEEPSEEK_API_KEY`
- CI：Key 走 Repository secrets；无 Key 时自动降级 Mock 模式

## 6. 准入 / 准出标准

**准入（开始测之前）**：接口可访问、Key 有效、`/docs` 能打开、基线用例（1 正常 + 1 缺字段）通过。

**准出（可以交付）**：
- P0 用例 100% 通过；P1 无阻塞性失败
- 效果评估平均分 ≥ 阈值（第 8 章定义，初定 8/10）
- 安全项（R9、提示词注入）零高危
- P95 时延 < 5s，单次平均 token ≤ 400
